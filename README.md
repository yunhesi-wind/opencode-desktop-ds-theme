# OpenCode Desktop DS Theme · 深海女仆玻璃主题

非官方 Windows 桌面主题改版：动态二次元背景、透明顶栏、深蓝色玻璃浮层及半透明消息气泡。
基于 [daemon1s/opencode-deepseek-chan](https://github.com/daemon1s/opencode-deepseek-chan)，
上游提交 `b59ba94581ffb2d48b4e180194c119c9661cab99`。由 **yunhesi-wind** 维护，包含 **OpenAI GPT** 辅助贡献。

**只发布源码，不分发背景视频、OpenCode 应用包或备份。** 用户在自己机器上构建并安装。
原作者及素材署名见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)，修改说明见 [CHANGELOG.md](CHANGELOG.md)。

## 效果与兼容性

- 深海女仆动态背景，静音循环；应用内半透明，不透出 Windows 桌面。
- 透明顶栏，操作按钮沿用原生状态背景，保留图标尺寸及原生窗口控制。
- 第二层上下文／会话栏使用模糊底色，减少滚动文本穿透。
- 摘要面板、二级选择菜单、左上角菜单及子菜单统一深蓝玻璃底色，**60% 不透明度**。
- 深蓝玻璃菜单、提问／权限确认、弹窗；白灰半透明已发送消息。
- 代码和浮层更通透；保留气泡发送状态变化及差异高亮的原生样式。

当前参数：菜单／摘要面板 60%、提问浮层 48%、代码底色 32%、已发送消息白灰底 62% 不透明度。
这些是 CSS 背景 alpha 值，并不是整个窗口的透明度。

动态视频和模糊合成会增加 GPU 开销；文字可读性和性能需在自己的设备上验收。

### 美术修改边界

仅调整配色、背景、透明度、模糊与阴影；不修改原生按钮尺寸／位置、布局、字体几何、UI 动画／过渡、点击行为或交互状态规则。顶栏按钮、菜单项和提问选项沿用原生 hover／焦点／按下／展开／禁用等状态；只通过颜色 token 随整体风格变化，不强制覆盖状态背景。分隔线只改已有边框颜色，不增加宽度；浏览器 `color-scheme` 仍由应用控制。

固定定位及 `pointer-events: none` 仅用于装饰背景，不用于应用控件。背景视频是装饰媒体，不属于 UI 交互动画。玻璃模糊可能影响合成／层叠，静态规则检查不等于真实视觉验收；需安装后检查菜单定位、键盘焦点、按钮状态、滚动和动画。

### 配色补齐第一轮

以 OpenCode 应用的**深色模式**作为当前视觉验收基准，请在应用设置中选择深色；脚本不改用户设置、不强制浏览器色彩模式。已补齐旧版控件底色、输入框、实际使用的弱／强图标变量、焦点与按下颜色、链接及部分语法颜色。提问选中底色通过组件局部颜色变量修正，避免浅色分支出现浅字浅底；这不代表已全面支持浅色／系统浅色模式。

- 会话及共享滚动视图：滑块蓝灰色，悬停／拖动时浅蓝灰；只改滑块局部颜色变量，不改尺寸、点击范围、位置、自动隐藏或动画。
- 文件树：通过现有 Shadow DOM 颜色接口调整滑块，不改原生 hover-only 显示规则。代码块原本隐藏的滚动条保持隐藏。
- 「技能」及同类 MCP／插件／LSP 二级菜单使用原生 overflow 滚动条，单独在 `.session-service-menu` 上设置蓝灰滑块／透明轨道；不改原生宽度、按钮、拖动或显示行为，不套用会话区自定义滚动条规则。
- 原生滚动容器配色扩展到明确的 19 个选择器：服务菜单、新版选择菜单内部滚动列表（包括外观的主题下拉框）、目录浏览、SSH 提示、设置导航／账号／WSL 列表、两代评论提及列表、消息导航预览、错误详情、项目扩展页、纵向设置标签列表、图片预览及 Markdown 表格／图表。只设置 `scrollbar-color`，不改隐藏规则。通用 `.overflow-*`、整个新版标签内容区和移动端混合内容容器不作全局覆盖，避免颜色继承进入文件／差异／终端等专用渲染区域。
- 已发送气泡：保留白灰底及 pending／sent 边界，加深提及前缀；合成底色极值的对比度测试不等于实际选中文本／视频画面的视觉验收。
- 文件／差异查看器：第一轮未作专用覆盖，后续第二轮的局部配色见下节；Markdown 代码底色 32% 参数不代表所有文件／差异视图同样透明。
- 内置终端：2.0.32 使用 Ghostty Canvas，本轮保留原生画布、ANSI、选区和滚动条，不用无效的全局 CSS 强行覆盖。
- 错误／成功／警告、差异红绿和反色提交按钮保留原生语义配色。本轮不增加模糊层或改变固定标题、弹层的层叠结构。

后续版本验收清单：会话／侧栏滚动条闲置→悬停→拖动→隐藏、长列表文件树、提问选中、按钮焦点／按下、白灰气泡提及、链接与代码可读性。涉及视觉修改时应先完成构建和用户验收，再推送主题及 OpencodeSelfuse 说明；本次验收已确认。

### 第二轮：文件／差异阅读配色

仅在应用原生深色模式的 `[data-component="file"]` 及其 `diffs-container` 主机上调整四个颜色变量：通过现有 `--opencode-diffs-bg` 接口设置不透明深蓝阅读底 `#101e33`、行号蓝灰 `#9aafc9`，搜索普通命中／当前命中分别采用两档琥珀色。保留原生搜索的 35%／55% 混合、定位与切换规则；只局部调整搜索使用的 warning 色，不修改其他警告界面。

不强制覆盖语法 token、增删行、词级强调、选区、评论、折叠、行号几何、虚拟化或动画。专用滚动条与内容底色共用变量，仍由原生规则派生，不为滑块强改上下文底色；内置终端继续原生。本轮不追求文件视图与 Markdown 代码块相同透明度，也不增加背景模糊层。

截图复核后追加：深蓝表面上，原生词级强调的浅色分支使用深红／深绿文字，出现低对比。现仅在文件主机及其 Shadow DOM 主机局部补齐 `--v2-red-1200`／`--v2-green-1200` 为浅红白／浅绿白，兼顾两种原生分支；不改强调背景、匹配范围或状态逻辑，不在全局改语义色。对比度回归按 2.0.32 原生增删行与词级强调的实际颜色、透明度叠加校验，本次已获用户验收确认。

HTML 文件预览属于独立 iframe，内部页面最外侧滚动条由该 HTML 自己的样式控制，应用主题不能跨文档直接覆盖；不向任意预览网页注入样式，不修改网页的布局或脚本。本次临时配色示例曾自行设置滚动条颜色，验收后已清理；示例不能当作所有原生组件的验收依据。

验证包括配色作用域、参考正文／行号对比度及本机原包中的接口检查，不代表每种语法颜色叠加搜索／差异高亮都已视觉验收。后续版本需回归普通文件、统一／分栏差异、红绿增删与词级强调、行号、选择文本／选中行、搜索全部／当前命中、折叠与长行横向滚动。

### 第三轮：固定阅读栏与浮层去重

- 恢复 `--surface-raised-stronger-non-alpha` 的不透明深蓝含义，供原生列表固定分组标题等需要遮挡滚动内容的区域使用。菜单仍使用 60% 玻璃底，提问／权限／弹窗仍使用局部 48% 底色，不把整个界面改成不透明。
- 仅对展开／锁定工具标题、差异汇总与差异标题，局部设置原生背景颜色变量，保留位置、层级、hover／pressed、滚动和动画规则；不额外增加模糊层。实机截图发现首页分组局部不透明变量会让原生渐隐伪元素形成突兀横条，现已移除该首页覆盖，恢复背景连续性；不调整会话条目阅读底色。
- 选择菜单按真实外层的 `data-component`／`data-slot` 配色，移除对任意 `role=menu/listbox` 的通用玻璃覆盖，避免外层浮层与内部语义列表重复叠加模糊／阴影。技能等服务菜单也明确按外层容器统一 60% 玻璃底。

原包接口与静态回归不替代实机验收。后续版本需回归：长会话滚动经过展开工具／差异标题、历史页分组横条／渐隐接缝、长列表固定分组、选择菜单键盘焦点、嵌套菜单和技能菜单的透明度。本次用户已确认修改生效、现有版本稳定。

用户确认的保留项：技能名称原生白底黑字悬停提示不改；会话条目直接叠在背景人物细节上不另加阅读底。主题下拉框内部列表仅补滚动条颜色，不重新叠加玻璃、阴影或模糊。

## 首次安装

```powershell
git clone https://github.com/yunhesi-wind/opencode-desktop-ds-theme.git
cd opencode-desktop-ds-theme
npm ci --ignore-scripts
```

先阅读素材声明。背景的 CC BY-NC-SA 4.0 信息仅来自上游，权利链未独立核实。
确认自己的使用权限后，再选择下载：

```powershell
node download-background.cjs --accept-upstream-license
# Windows 开启了系统代理时：
node download-background.cjs --accept-upstream-license --system-proxy
# 或显式提供代理：
node download-background.cjs --accept-upstream-license --proxy http://127.0.0.1:7897
```

下载器校验现有缓存及新下载的大小和 SHA-256，不使用第三方镜像，不执行下载内容。
也可以自行将上游同一视频放到 `assets/zipzip-1080p.mp4`；内容仍必须匹配固定哈希。

构建（不改变已安装应用）：

```powershell
node deploy.cjs prepare
```

**保存工作，完全退出 OpenCode 桌面版**，再双击 `Install-Theme.cmd` 或执行：

```powershell
node deploy.cjs install
```

重新打开后检查视频播放、菜单、问题面板、代码区、内置终端及滚动性能。
脚本不强制终止桌面进程，不修改会话数据库、模型、skills、MCP 或凭据。

## 更新主题与恢复

在同一目录更新源码后重新 `prepare`，退出桌面版再安装；构建会复用经校验的干净原包。
当前应用哈希未知、版本不同、原生文件或素材校验失败时拒绝覆盖。

### OpenCode 更新到更高的已支持版本后（当前支持至 2.0.32）

官方更新会覆盖美化资源；旧 manifest 不可直接用于安装或恢复新版。
**保存工作并完全退出桌面版**，双击 `Upgrade-Theme.cmd`，或执行：

```powershell
node deploy.cjs prepare --upgrade
node deploy.cjs install
```

只有第一条成功后才能安装。升级构建使用当前新版原包，独立校验原生文件；
保留旧 snapshot、备份及 `previous-manifest.json`，不继承旧版主题哈希。
`--upgrade` 只允许更高的已支持版本，不放行未知版本、降级、同版本未知修改或已美化原包。
构建时无需退出桌面版，但安装时必须退出；脚本不会强制结束进程。

恢复：退出桌面版，双击 `Restore-Theme.cmd` 或执行 `node deploy.cjs restore`。
主题包损坏／丢失不阻断原包恢复，原始 snapshot 不可用时查找验证过的备份。
若主 manifest 损坏，可以指定备份目录：

```powershell
node deploy.cjs restore --backup ".\backups\<版本与哈希目录>"
```

**不要删除 `prepared/` 或 `backups/`，不要在应用更新后恢复旧版本。**
此入口仍拒绝覆盖未知版本，备份 metadata 记录已安装的主题哈希。

### 验收后的本机清理

只清理确认无用的中间产物，不删除整个 `prepared/` 或 `backups/`。先确认已安装 ASAR 匹配当前 `prepared/manifest.json`，并验证当前主题包、原包及备份后，保留 manifest 的 `output` 与 `snapshot` 所在构建目录、当前版本备份及其 metadata；其他同版本中间构建可按目录清理。历史 `previous-manifest.json` 只是构建记录，不保证已清理的中间主题包仍可回退。

截图、临时示例 HTML、截图辅助脚本和隔离测试残留可在验收后清理；不删除背景素材、源码、依赖、当前恢复资源或任何会话／个人配置。CLI 项目备份不属于桌面主题清理范围。
